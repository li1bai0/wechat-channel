# Claude 后端常驻：不每条消息冷启动

## Problem
Claude Code 后端原本每次回复都 `claude -p` 拉起一个全新进程，`--resume` 只能续会话内容、进程照样重启。每条消息都要重新加载 CLAUDE.md、MCP 工具定义等完整资料（实测固定开销约 10-18k input tokens），冷启动慢（约 10-12 秒），走 deepseek 代理时没有 prompt caching、全量重付。

## Decision
给 claude 后端加常驻 helper（`scripts/claude_helper.py`）：用官方 Python SDK 的 `ClaudeSDKClient` 保持一个常驻 claude 子进程，多轮对话复用同一进程，CLAUDE.md/MCP 只在启动时加载一次。桥与 helper 走 stdin/stdout JSON 行协议（与 `codex_ws_helper.mjs` 对等）。会话续接/切换：新会话自动重启子进程并 `resume` 磁盘 transcript（进程重启也不丢上下文）。人设底稿只在新会话注入一次，续接不重复喂。

## Alternatives considered
- 保持 spawn 模式（原方案）：冷启动 + 全量加载，每轮浪费 10-18k token，不采用。
- 官方 TS SDK `query()`：每次调用同样 spawn 新进程（GitHub issue #32 实锤），无常驻客户端，不采用。
- 第三方常驻服务（nx-ce 等）：额外依赖、未经验证，不采用。
- 让 wechat-claude-code（Claude 侧 node 桥）自己实现常驻：与桥内 helper 重复造轮子，统一走 `claude_helper.py` 协议，任何桥都能接。

## Consequences
常驻后每轮回复约 1-2 秒、固定开销只在启动时付一次。可靠性靠三层兜底：helper 内子进程崩了自动重启续接；桥 HANG 检测（3 次）后重启 helper 自愈；helper 不可用自动回退旧 spawn 模式保底。代价：helper 依赖 `pip install claude-agent-sdk`（文档已注明）；常驻单进程串行处理 turn（claude 后端不支持定向打断，与之前一致）。
