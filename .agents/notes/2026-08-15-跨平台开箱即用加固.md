# 跨平台开箱即用：codex 原生/npm 双探测 + 非 Windows 兜底

## Problem
仓库最初只为“本机 + npm 安装的 Codex”设计：codex 只探测 `node_modules/@openai/codex/bin/codex.js`；`_pid_alive`/`_kill_stray_helpers`/`_toast` 依赖 PowerShell/ctypes（macOS/Linux 靠异常兜底，单实例锁会误判）；README 未提首次登录。换一台机器（原生 codex CLI / macOS / Linux）会直接踩坑。

## Decision
- codex 探测扩展：`shutil.which("codex")` → `~/.codex/bin/codex(.exe)` → `~/.local/bin/codex` → npm `codex.js`；解析到非 `.js` 即 `CODEX_NATIVE=True`，`_ensure_app_server` 用 `[codex, app-server ...]` 而非 `[node, codex.js, ...]`（helper 仍需 Node，README 注明）。
- 非 Windows 兜底：`_pid_alive` 用 `os.kill(pid,0)`；`_kill_stray_helpers` 用 `pkill -f`；`_toast` 直接跳过。
- README：明示 macOS/Linux 可运行、Node 18+ 必需、首次使用先 `codex login` / `claude login`（或 `ANTHROPIC_API_KEY`）。

## Alternatives considered
- 强制只支持 Windows + npm：违背开源定位，不采用。
- 全部用 psutil 跨平台进程管理：引入第三方依赖，`os.kill`/`pkill` 已够，不采用。
- 让 helper 也脱离 Node：改动大、收益低，不采用。

## Consequences
原生与 npm 两种 Codex 安装、三平台均可开箱运行；代价：多几个探测路径（一次性），Node 依赖仍需满足并已写明。
