# 回复队列丢失唤醒：Event 竞态导致“完成一个不继续下一个”

## Problem
两个 reply worker 线程用 `threading.Event` 实现任务队列唤醒：worker 在 `wait()` 返回后检查队列，若为空则 `clear()` 后继续等；生产者 `appendleft + set()`。竞态窗口：worker 检查到队列为空之后、`clear()` 之前，生产者恰好入队并 `set()`，随后 worker 的 `clear()` 把唤醒信号清掉 → 队列里已有任务，但所有 worker 都阻塞在 `wait()`，任务永久不处理。现象就是“一个任务完成了，下一条卡住不动”，且进程活着、看门狗不触发，极难定位。

## Decision
队列唤醒改用 `threading.Condition`：消费者 `with cond: while not reply_q: cond.wait(); text = reply_q.popleft()`，生产者 `with cond: appendleft + cond.notify()`。worker 循环外层再包一层 try/except，避免单条消息异常杀死 worker。

## Alternatives considered
- 保留 Event 只修 clear 时序：仍无法保证“检查-清信号-入队”之间不丢唤醒，不采用。
- 退回单 worker 串行：牺牲多消息并发能力，不采用。
- `queue.Queue` + `task_done`：并发语义更标准，但要额外引入停止/监控机制，改动面更大，不采用。

## Consequences
消除丢失唤醒，多 worker 并发保留，单条异常不再杀死 worker。代价：生产者/消费者两处改动，需重启桥生效。
