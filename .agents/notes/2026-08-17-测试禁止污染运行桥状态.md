# 测试桥逻辑必须隔离 state，禁止直接操作运行桥的状态文件

## Problem
2026-08-17 中午为验证「模型分档 / 降档重试」直接 `import` 桥模块并构造 `Bridge()` 实例跑 `_process_one`/`_process_task`，monkeypatch 的 `agent_reply` 返回假会话 ID（短字符串，非 UUID）。Bridge 实例与运行中的桥共用同一个 `state.json`，`_process_one` 的 `self.state["codex_session"] = new_sid` + `save_state()` 把假 ID 写进状态文件；假任务文本也进了 `task_queue`，桥重启后真的执行了三个假任务并给老板发了回复。此后老板所有聊天消息续接坏线程全部 `invalid thread id`，连回「暂时连不上模型服务」约 2.5 小时。

## Decision
- 测试任何会写 state 的桥逻辑时，必须用独立临时 state 文件（构造 Bridge 前替换 `DATA_DIR`/state 路径或直接备份恢复），禁止在运行中的桥上直接 import 测试。
- 只做只读验证时不得调用会 `save_state()` 的方法；需要验证回复生成时用假后端 + 临时工作目录。
- 事故现场修复：备份 `state.json` → `codex_session` 置 null、删除假任务 sessions → 重启桥重载内存 state。

## Alternatives considered
- 只改文件不重启桥：桥内存里仍持有坏的 `codex_session`，下次 `save_state()` 会覆盖回污染值，必须重启。
- 认为测试只影响测试实例：`Bridge()` 与运行桥共享同一 state 文件，写入会持久化，无隔离就是污染。

## Consequences
老板微信通道中断 2.5 小时（15:13-18:20）。代价是运行环境状态被测试污染；收益是明确了测试隔离纪律：本地 mock 测试必须走临时目录，杜绝再次把假会话 ID/假任务写进生产 state。
